# Baseline agent evaluation — 2 November 2026

The baseline passed **57/100 questions (57%)** under the existing Promptfoo assertions: **43 assertion failures, 0 runtime errors**. Answer quality passed **66/100**, workflow behavior passed **76/100**, and all 100 responses were nonblank. **All 653 Python tests passed**, including PostgreSQL integration checks; none were skipped.

The highest-scoring tag was `extra_calculation` (90%), followed by `conditional_reasoning` (80%). The lowest were `in_domain_no_data` (0% strict, 80% answer quality) and `out_of_distribution` (20% strict, 100% workflow). The strict score therefore combines factual ability with routing contracts, citation requirements, and grader judgments. It is not a pure financial-accuracy rate.

Mean time to a complete answer was **21.42 s**, median **19.56 s**, and p95 **48.80 s**, at four concurrent evaluation cases. Estimated API cost for the 100-question run was **$0.740769**: **$0.627522** for the agent including query embeddings and **$0.113247** for grading. These are usage-based USD estimates, not a billing statement.

## Retrieval attempts, failures, and evidence coverage

- **58/100** questions invoked retrieval; **42/100** did not. Graph rounds totaled **77**. Company-specific calls totaled **95** and produced **760 chunk returns** (eight per call), with 95 embedding responses and 4,518 embedding input tokens.
- Observed callback errors: **0/95 retrieval calls**, **0 empty retrieval results**, **0/235 model-call errors**. These are execution metrics, not evidence that the retrieved material answered the question.
- Seven retrieved questions ended with the model judging context insufficient: **ACC03, ACC05, TOOL08, MUL01, IMG09, TAB01, TAB09**. Three still passed the strict evaluation. Thus sufficiency assessment is not a reliable standalone correctness metric.
- Eleven of the 58 retrieved questions used another round (**19.0%**); eight reached the three-round cap (**13.8%**). Cap use is a difficulty/effort indicator, not automatically a retrieval failure.
- Retrieval/embedding/database time totaled **31.82 s**, averaging **0.335 s per company call**, approximately **1.5%** of summed complete-answer latency. This excludes the model's query planning and sufficiency reasoning.
- There were **112 repeated chunk returns within the same question (14.7% of 760)**. The 648 remaining returns are unique within each question, not globally unique across the entire dataset. Repeated context can increase prompt size.

### Findings that matter for the baseline

1. **Routing loses available factual answers.** Twelve grounded requests stop at clarification. Examples include ACC10 (Netflix 2025 EPS), TAB02 (Amazon interest expense), TAB04 (Meta R&D), and TAB10 (Netflix tax provision). MUL06 and MUL09 incorrectly treat the Meta FY2025 annual filing as absent because coverage labels mention FY2025 Q4. IF07 similarly treats comparative 2024 figures inside the retained 2025 annual filing as unavailable. This confuses document coverage with the periods discussed inside a document. Some question wording is underspecified, notably IMG07's unnamed fiscal deck, so these cases also merit fixture review.
2. **Vector hits can miss the required evidence.** ACC03 retrieves Apple's annual report but misses the Services amount; after three rounds it cannot report the expected $109.158 billion. TOOL08 and IMG09 fail to retrieve the retained Alphabet Q4 2025 slide deck at all, instead returning older slide decks and annual-report text. They incorrectly generalize a search miss into a statement that the deck is unavailable. These are evidence-recovery failures despite zero empty-result or execution errors.
3. **Some answers use the wrong entity/metric within a correct deck.** IMG02 returns 41.9% as Alphabet Q4 operating margin instead of 31.6%, reversing the comparison with the 32.0% annual margin; the expected page was in retrieved context. IMG05 returns Amazon chart values 10,632/12,465 from p.11 instead of the requested 21.203/24.977 billion from p.5. IMG01 omits the millions scale after copying 402,836 from a chart.
4. **Citation quality and numeric quality are separate.** ACC01 gives the expected $402.836B but uses generic `PDF` labels and pages the judge does not accept as an unambiguous equivalent of the reviewed 10-K citation. ACC04 gives the expected $60.458B using an earnings release where the fixture requests the annual filing. The expected annual PDFs were retrieved in both cases, but the reviewed pages were not.
5. **A final response can fail even with a valid trajectory.** TAB09 completes three retrieval rounds, has evidence labels, and passes the workflow assertion, yet its final answer is only “I'll retrieve…” with no EPS figure. The current nonblank/citation-metadata checks do not ensure that the requested task was completed. Provider citations list retrieved evidence, not necessarily citations actually used in the answer.
6. **The no-search arithmetic control fails.** TOOL10 routes out of domain instead of calculating $120M − $75M = $45M. This is a bounded capability/routing issue rather than a database problem.

### Evaluation contracts and grader limits

- **NOD02–NOD09:** all eight have answer-quality passes and explicit unavailable-evidence responses, but fail because the deterministic missing-data assertion requires retrieval. The documented baseline deliberately returns known company/period gaps without retrieval. Excluded companies cannot legally be selected by the five-company retrieval tool. This is a contract mismatch; forcing arbitrary searches would obscure the intended scope policy.
- **NOD01 and NOD10 are additional response defects.** NOD01 gives only the generic out-of-domain sentence rather than identifying Walmart's absence; NOD10 asks for a list of 15 companies without clearly stating that only five are indexed. Both fail quality as well as workflow and should not be treated as the same issue as the eight quality-passing gap responses.
- **AMB04:** the agent supplies the correct fiscal sales figure and fiscal year-end date. Quality passes, but workflow demands `needs_clarification` with no retrieval. **AMB07:** the agent asks exactly for the missing metric and baseline, but the grader rejects it for lacking an annual-report citation even though workflow forbids retrieval. **AMB09:** the fixture expects a cited factual explanation of quarterly versus annual growth while the tag-wide workflow requires a clarification with no retrieval. The agent clarifies and fails quality. These expose inconsistent route/source expectations.
- **Out-of-domain cases:** all ten correctly take the refusal route with no retrieval or report citations. Eight fail the quality grader mainly for insufficient request-specific explanation or redirection; some reasons also demand corpus citations on an out-of-domain refusal. OOD04 and OOD05 pass with the same fixed refusal sentence. This shows grading sensitivity and means the 20% strict result should not be described as an 80% unsafe-compliance rate.
- **A passed case still exposes a blind spot.** MUL01 correctly names Amazon as largest and passes, but does not retrieve Meta and falsely claims its FY2025 annual report is absent. The correct winner does not validate complete comparison evidence. This is an example of a potential false positive, not a post-hoc score correction.
- **Smoke-run variability:** ACC01's first verification run passed, while the second smoke run and full run failed over source citation despite all three giving the correct numeric revenue. Neither a single grader outcome nor a single wording variant establishes stable reliability.

## Recommendations for a later iteration — not implemented

1. **Align evaluation contracts first.** Explicitly allow verified manifest-based known-gap responses without retrieval; define when clarification needs citations; give AMB09 a workflow expectation compatible with its factual answer. Adjudicate the flagged cases and add deterministic checks for numeric amounts, units, and refusal routing where feasible. Keep the current 57% result as the original-contract baseline and version any revised suite separately.
2. **Review routing against retained documents and comparative columns.** Distinguish a missing source report from an earlier-year figure available in a retained annual report. Establish consistent annual-period defaults and retain clarification only for material ambiguity. Re-evaluate the 12 factual clarification failures and TOOL10 as a targeted subset before a full rerun.
3. **Target the known evidence misses.** Evaluate document/report-type/fiscal-period narrowing, hybrid search, and reranking for the Q4 Google Cloud deck and Apple Services table. Use the frozen exact-source/page hit measures to compare alternatives. Deduplicate repeated chunks and bound accumulated context before increasing retrieval depth.
4. **Improve evidence identity and chart grounding.** Preserve canonical report name/path, page, metric, entity, period, and units in answer citations. Verify the selected chart is the consolidated or segment metric requested. Test source/page selection and unit preservation, rather than merely the presence of retrieved citations.
5. **Validate completion and comparisons.** Reject a final progress message such as TAB09, and check that required companies have evidence before making a five-company conclusion such as MUL01. Assess whether the sufficiency model is calibrated against actual answer quality.
6. **Measure changes as controlled comparisons.** Reuse the pinned 100 PDFs and versioned suite; run the same concurrency and cache settings; report strict/quality/workflow deltas separately plus cost and latency. Repeat judge-sensitive cases and manually adjudicate representative positives and negatives. Retry cohorts differ in difficulty, so their descriptive rate comparison is not an architectural ablation.
